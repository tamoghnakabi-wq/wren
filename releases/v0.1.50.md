- Security on Mac: a command an agent runs can no longer start anything outside Wren's sandbox. Opening an app it built with `open`, telling another app what to do with AppleScript, and reaching other programs' sockets (Docker's, a terminal's, an editor's or a browser's) all ran with your full access before. Commands can still use sockets in the folders you allowed and in their own temporary folder, and your local Postgres or MySQL.
- Agents can show you things on your screen again, through Wren: a PDF, image, text or media file opens in Preview, TextEdit or QuickTime Player; other files and folders are shown in Finder; a web link opens in your browser after you approve it. Claude Code gets the same as Wren's open tool.
- Docker works for agents through Wren on Mac. Containers can mount the folders you allowed (whole or a folder inside them), and `docker compose`, `docker build` and `docker exec` work. Containers can't mount other folders of your Mac or the Docker socket, can't run privileged, and agents can't run commands in a container that has the Docker socket. To mount folders, allow the project folders themselves rather than your whole home folder.
- Agents can stop a background job they started (to restart a dev server, say) without asking you.
- Fewer needless approvals: the word "open" in a script or a commit message, `ls .env*`, `cp .env.example .env`, a project's own `.vercel` folder, `git clone http://…` and `docker run --rm` no longer count as risky. Reading a `.env` file still asks, also when Claude Code reads it with its own tools.
- Agents now ask before reading, sharing or changing files with credentials (`.env`, `.npmrc`, SSH keys and the like) by any route, whether a shell command, a file tool or Grok Build. Wren's file tools never touch credential stores such as `~/.ssh` or `~/.aws`, on Windows too.
- With terminal access off, Claude Code gets no terminal at all, even for commands it counts as read-only.
- Grok Build tools Wren doesn't know yet ask for approval instead of being guessed at.
- GitHub organisation and SCIM changes always ask, like other organisation settings.
