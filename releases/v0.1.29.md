- Claude Code's own file tools can no longer read or change Wren's settings and data, Wren itself, credential folders such as ~/.ssh, or Grok Build's sign-in, even when you've allowed a folder that contains them (such as your home folder).
- Wren no longer falls back to a browser downloaded into a cache folder agents can write: agents use Google Chrome or Microsoft Edge. Wren also won't start Claude Code or Grok Build from a place agents could have changed, and says why.
- Grok Build's own program and shell completions are protected from agents' commands.
- A page that relabels a field as a password field while Wren types a key into it, even from its own input handlers, no longer gets the text; Wren takes it back out and says the field changed.
- Deleting a home folder or a whole drive is also blocked when it's one item of a PowerShell list, or written with cmd's rd /s or .NET's Directory.Delete.
- Notes agents saved earlier are passed to them as notes, not instructions.
- Sign-in scripts that couldn't open Terminal now say so, and service-worker notifications in the Wren window keep working.
